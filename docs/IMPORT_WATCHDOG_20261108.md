# Bounded actual-project import continuation
The active Windows job is left unchanged until its checkpoint completes. The next dispatched continuation uses a per-source active marker and an external launcher. One identified source exceeding twenty minutes is stopped within only the editor process tree launched by that wrapper. Its source and partial output remain intact and its SHA256 is recorded for review; other source imports can continue in the next batch. Unknown startup failures never mark arbitrary models failed. The total owned process budget is fifty-five minutes.

The wrapper reads durable accepted/error ledgers before starting Unreal. When no source remains pending, it writes a summary and avoids an unnecessary editor startup. A zero pending count still includes a separate failed-source count; it does not mean every model passed.

Four local receipt regression tests passed: completed assets remain unchanged after a source timeout; unknown/changed source identity is rejected; an accepted source is never reclassified failed; failed sources remain distinct from accepted sources. Native Windows process termination and large-model behavior remain to be validated on the actual runner. No actual model is claimed optimized or gameplay-ready by this change. The continuation workflow is dispatch-only so source maintenance cannot accidentally start duplicate import campaigns.
