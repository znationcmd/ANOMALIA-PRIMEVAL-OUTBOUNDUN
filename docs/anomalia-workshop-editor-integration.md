# ANOMALIA Editor → Mod Workshop → Solo / CMD Hosting
Editor workflow: create original assets, buildings and map placements; validate, version, package for Unreal; publish signed manifest + SHA-256; display mod in in-game catalog; user explicitly approves installation; download to temporary directory, verify size/hash/signature, check dependency graph and compatibility, atomically install to sandboxed mod directory, enable and restart/reload safely. For server join, compare the server-required mod manifest and client installation; prompt to install missing versions, then join. For solo, use the same resolver and local installed manifest. For CMD Hosting, use server-side manifest, isolation and deployment via Hosting API.

The pure resolver in `src/mod-manager.js` validates metadata and resolves dependencies, but **does not download or mount Unreal packages**. UI, mod authoring and publication, hosting API, signature verification implementation, native Unreal pak/IoStore mounting, multiplayer version handshake, per-server persistence and tests are still required. `mods.json` remains disabled intentionally until secure end-to-end implementation.

Mapping: `mapping/platform-paths.json` reserves DayZ-console-style aliases `dayzps_missions` / `dayzxb_missions` and `custom`, but ANOMALIA is a separate game; no actual Nitrado DayZ folder is used. Editor mapping exports remain in `mapping/exports/` until an Unreal loader is connected. Existing files and mapping exports are preserved.
